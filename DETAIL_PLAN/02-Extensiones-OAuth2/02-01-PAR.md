# 02-01 — PAR: Pushed Authorization Requests — RFC 9126

**Prioridad:** P2  
**Spec:** RFC 9126  
**Esfuerzo estimado:** Medio (3-4 días)  
**Dependencias previas:** 01-01 PKCE  
**Habilita:** authorize flow sin parámetros sensibles en URL del navegador

---

## Contexto

En el authorize flow estándar, todos los parámetros (`client_id`, `scope`, `redirect_uri`,
`code_challenge`, `state`, `nonce`) viajan en la URL del navegador y pueden ser
interceptados, loggeados por proxies, o manipulados. PAR resuelve esto en dos pasos:

1. El cliente hace un POST directo al servidor con todos los parámetros (server-to-server)
2. Recibe un `request_uri` de un solo uso y corta duración
3. El navigate del usuario al `/authorize` solo incluye `client_id` y `request_uri`

---

## Qué implementar

### Endpoint PAR

```
POST /openid/{tenant}/par
Authorization: Basic base64(client_id:client_secret)
Content-Type: application/x-www-form-urlencoded

response_type=code&client_id=xxx&redirect_uri=https://...&scope=openid+email
&code_challenge=xxx&code_challenge_method=S256&state=yyy&nonce=zzz
```

Respuesta:
```json
{
  "request_uri": "urn:ietf:params:oauth:request_uri:abc123xyz",
  "expires_in": 60
}
```

### Authorize con request_uri

```
GET /openid/{tenant}/authorize?client_id=xxx&request_uri=urn:ietf:params:oauth:request_uri:abc123xyz
```

El servidor recupera los parámetros almacenados y continúa el flujo normal.

```sql
CREATE TABLE IF NOT EXISTS _oauth_par_request (
  request_uri  VARCHAR(100) NOT NULL,
  tenant_id    VARCHAR(36)  NOT NULL,
```

### C. Domain — ParRequest

```php
final class ParRequest
{
    public function __construct(
        public readonly string $requestUri,     // "urn:ietf:params:oauth:request_uri:{random}"
        public readonly string $tenant,
        public readonly string $clientId,
        public readonly array  $params,         // todos los parámetros del authorize
        public readonly \DateTimeImmutable $expiresAt,
    ) {}

    public static function create(string $tenant, string $clientId, array $params): self
    {
        $token = bin2hex(random_bytes(32));
        return new self(
            requestUri: "urn:ietf:params:oauth:request_uri:{$token}",
            tenant: $tenant,
            clientId: $clientId,
            params: $params,
            expiresAt: new \DateTimeImmutable('+60 seconds'),
        );
    }

    public function isExpired(): bool
    {
        return $this->expiresAt < new \DateTimeImmutable();
    }
}
```

### D. Application — PushAuthorizationUsecase

```php
public function push(PushAuthorizationParams $params): PushAuthorizationResult
{
    // 1. Autenticar cliente (Basic Auth o client_secret_post)
    $client = $this->clientStore->findByClientId($params->clientId, $params->tenant);
    if (!$client || !hash_equals($client->secret, hash('sha256', $params->clientSecret))) {
        throw new OAuthException('invalid_client');
    }

    // 2. Validar parámetros básicos (redirect_uri, response_type, scope)
    $this->validateAuthorizeParams($params->authParams, $client);

    // 3. Crear y almacenar PAR request
    $parRequest = ParRequest::create($params->tenant, $params->clientId, $params->authParams);
    $this->gateway->store($parRequest);

    return new PushAuthorizationResult(
        requestUri: $parRequest->requestUri,
        expiresIn: 60,
    );
}
```

### E. AuthorizeHtml — soporte para request_uri

**Archivo:** `src/Features/Oidc/Authentication/Infrastructure/Driver/Html/AuthorizeHtml.php`

Al inicio del authorize flow, si `request_uri` está presente:
```php
if (isset($queryParams['request_uri'])) {
    $parRequest = $this->resolveParUsecase->resolve($queryParams['request_uri'], $tenant);
    if ($parRequest === null) {
        return $this->errorResponse($response, 'invalid_request_uri');
    }
    // Reemplazar queryParams con los del PAR
    $queryParams = array_merge($queryParams, $parRequest->params);
    // Marcar como usado (single-use)
    $this->parGateway->markUsed($queryParams['request_uri'], $tenant);
}
```

## Tests a incluir

### Test unitario — ParRequest

- `create()` genera URI con prefijo correcto `urn:ietf:params:oauth:request_uri:`
- `isExpired()` con expiresAt pasado → `true`
- `isExpired()` con expiresAt futuro → `false`

### Test unitario — PushAuthorizationUsecase

Con mocks de `ClientStoreGateway` y `ParRequestGateway`:
- Credenciales válidas + params válidos → devuelve `PushAuthorizationResult` con `request_uri`
- Credenciales inválidas → excepción `invalid_client`
- `redirect_uri` no registrada → excepción `invalid_request`

### Test integración — POST /par

- Request válido → `201` con `{ request_uri, expires_in: 60 }`
- Sin autenticación → `401`
- `GET /authorize?request_uri=...` con URI válida → flujo normal continúa
- `GET /authorize?request_uri=...` con URI expirada → error `invalid_request_uri`
- Mismo `request_uri` usado dos veces → segundo intento falla (single-use)
