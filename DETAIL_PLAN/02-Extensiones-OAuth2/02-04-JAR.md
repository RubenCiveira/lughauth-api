# 02-04 — JAR: JWT Secured Authorization Requests — RFC 9101

**Prioridad:** P4  
**Spec:** RFC 9101 (actualiza OpenID Request Object de OIDC Core §6)  
**Esfuerzo estimado:** Medio (2-3 días)  
**Dependencias previas:** 02-01 PAR (recomendado, pero independiente)  
**Habilita:** parámetros de autorización firmados y no repudiables

---

## Contexto

JAR permite al cliente enviar todos los parámetros del authorize como un JWT firmado
(parámetro `request`) o referenciado remotamente (`request_uri`). Esto garantiza
integridad (no pueden ser modificados en tránsito) y autenticidad (el servidor puede
verificar que los parámetros vienen del cliente legítimo).

---

## Qué implementar

### Parámetro request en authorize

```
GET /openid/{tenant}/authorize
  ?client_id=xxx
  &request=eyJhbGciOiJSUzI1NiJ9.eyJyZXNwb25zZV90eXBlIjoiY29kZSIsImNsaWVudF9pZCI6Inh4eCIsInJlZGlyZWN0X3VyaSI6Imh0dHBzOi8vLi4uIn0.sig
```

El JWT `request` contiene todos los parámetros del authorize como claims del payload.

## Dónde y cómo hacer los cambios

### A. Campos en access_trusted_client

```sql
  ADD COLUMN request_object_signing_alg VARCHAR(20) NULL,   -- RS256, ES256, PS256, none
  ADD COLUMN jwks_uri                   VARCHAR(500) NULL,  -- JWKS público del cliente
  ADD COLUMN jwks_json                  TEXT NULL;          -- JWKS inline del cliente
```

### B. Domain — RequestObjectValidator

**Archivo nuevo:** `src/Features/Oidc/Authentication/Domain/RequestObjectValidator.php`

```php
final class RequestObjectValidator
{
    public function __construct(
        private readonly HttpClientInterface $http,  // para fetch de jwks_uri
    ) {}

    public function validate(string $requestJwt, ClientData $client): array
    {
        // 1. Parsear header del JWT para obtener alg y kid
        $header = $this->parseHeader($requestJwt);

        // 2. Obtener clave pública del cliente (jwks_uri o jwks_json)
        $jwks = $this->fetchClientJwks($client);

        // 3. Verificar firma con web-token/jwt-bundle
        $payload = $this->verifySignature($requestJwt, $jwks, $header['alg']);

        // 4. Validar claims requeridos
        if (($payload['client_id'] ?? null) !== $client->clientId) {
            throw new \InvalidArgumentException('client_id mismatch in request object');
        }

        // 5. Devolver array de parámetros verificados
        return $payload;
    }
}
```

### C. AuthorizeHtml — procesar parámetro request

**Archivo:** `src/Features/Oidc/Authentication/Infrastructure/Driver/Html/AuthorizeHtml.php`

Al inicio del authorize, antes de construir `OidcFlowContext`:
```php
if (isset($queryParams['request'])) {
    $client = $this->clientStore->findByClientId($queryParams['client_id'], $tenant);
    $verifiedParams = $this->requestObjectValidator->validate($queryParams['request'], $client);
    // Los parámetros del JWT tienen precedencia sobre los query params
    $queryParams = array_merge($queryParams, $verifiedParams);
}
```

## Tests a incluir

### Test unitario — RequestObjectValidator

Con mock de `HttpClientInterface`:
- JWT firmado con RS256 válido → devuelve claims del payload
- JWT con `client_id` diferente → excepción
- JWT con firma inválida → excepción
- JWT con alg `none` → excepción (rechazar alg=none siempre)

### Test integración — authorize con request object

- GET /authorize con `request=<JWT válido RS256>` → flujo normal
- GET /authorize con `request=<JWT firma inválida>` → error `invalid_request_object`
- GET /authorize con `request=<JWT alg=none>` → error
