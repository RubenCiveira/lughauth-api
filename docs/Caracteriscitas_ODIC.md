# Características OIDC: modelo funcional común para pruebas PHP y Java

> Corte: árbol PHP consultado el 21-10-2026. OIDC es el nombre del protocolo; se conserva `Caracteriscitas_ODIC.md` como nombre solicitado. Esta matriz describe **LughAuth PHP** y sirve como lista de contratos compartidos para los tests de PHP y Java. No certifica el estado del código Java: la comparación histórica con Phylax está en [ANALISIS_DESARROLLOS_OAUTH_2.md](ANALISIS_DESARROLLOS_OAUTH_2.md) y puede estar desactualizada.

**Lectura:** «Actual» significa ruta o lógica presente, no conformidad demostrada; «parcial» identifica una ruta existente cuyo contrato aún tiene huecos. «Futuro» es el comportamiento objetivo según `docs/TODD/`; las tareas en [`done/`](TODD/done/) se consideran incorporadas al estado actual, no pendientes. «Opcional» requiere decisión de producto. Los ejemplos de test son aserciones de caja negra reutilizables en ambos lenguajes; si una extensión no está habilitada, comprobar que no se anuncia ni se acepta. Los endpoints bajo `/oauth/openid/{tenant}` son relativos al issuer canónico de ese tenant.

## Regla para mantener la matriz sincronizada

Al cerrar una tarea, contrastar **ruta**, **lógica**, **metadato discovery** y **prueba observable**; mover el comportamiento de «Futuro» a «PHP actual» solo cuando se verifique en el árbol y añadir el mismo caso funcional al conjunto de pruebas Java. La fuente de estado de las tareas son las fichas de [`TODD/`](TODD/) (incluido `done/`); el [inventario de épicas](TODD/epicas/README.md) y [MODELO_Y_ESQUEMA_018-071.md](TODD/MODELO_Y_ESQUEMA_018-071.md) son guías de diseño y pueden describir estados anteriores a los cambios ya integrados.
